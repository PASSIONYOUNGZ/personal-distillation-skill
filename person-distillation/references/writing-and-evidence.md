# 内容理解、证据和文案质量

先读足够原文或完整稿，长材料按章节分块，最终核首尾和章节连接。搜索摘要、目录、章节列表只作定位，不替代全文。重要配图中的流程、代码、比较数据和操作路径必须实际查看，无法辨认的部分明确记录。

一张好卡片让新读者知道：讨论什么具体问题、作者怎样做、关键选择为什么、哪些条件下适用、可以学什么。短材料可以短，复杂方法保留解释和例子；不统一凑字数，也不把工具名清单当方法。

内部重要判断关联证据：来源ID、URL／本地快照、段落／时间／页码、支持的事实、本人自述／外部记录／分析、反例。输出选直接原链或时间定位，不堆无关引用。

| 位置 | 写什么 | 避免 |
| --- | --- | --- |
| 首页身份 | 姓名与简明身份定位，配已核头像、账号和范围入口 | 再放一段人物简介；宣传口号、猜职位、把封面人物当本人 |
| 认识这个人 | 一个完整段落说清主要角色、代表实践及有证据特点；来源集中可查 | 分四节写成第二条履历；逐年重复时间线；无关未知免责声明；预先列末尾学习建议 |
| 经历时间线 | 整体公开经历、角色变化及事件日期依据，不受作品选集窗口限制 | 用近几篇作品凑履历；文章发布日期冒充转岗日期；补未知月份 |
| 内容简介 | 通常1—3句，具体对象、问题、作者的动作或主要观点，必要条件 | “分享AI经验，值得学习”等通用空话；把推荐理由当内容介绍 |
| 内容解读 | 问题→做法→理由→条件＋原作例子 | 理想流程安给作者；只有结论没有解释 |
| 学习方向 | 直接教到、可迁移、需另学的基础分别说明 | 指定必学清单；没实践就写已掌握 |

例如“分享产品思维”过于空泛；若材料确实支持，可写“作者复盘一个写作工具：整篇重写让用户难以核对变化，于是改为逐项修改建议。文章解释建议如何定位到原句，以及用户怎样选择采纳。”这先交代原内容，再解释其做法；“值得学会控制自动化”留给学习分析。作者演示成功不等于我们已复现。

内容简介以让读者知道讲什么、是否值得进入全文为准。简单短帖不强凑三句，复杂材料不压成标签；桌面约1—3行是布局目标，不是字数上限。不能为适应固定列宽删必要条件、硬截断、缩成注释字号。手机和文字放大时自然增行。主体归属分清作者、团队同事与被转述者，不把同事的作品安给作者。

首页、人物介绍、经历和末尾学习方向各有职责。首页只用姓名与身份定位识别人；biography用一段连贯文字介绍整体角色、主要工作、代表实践与有依据特点，不再拆成多个履历小节。年份、转折及其证据放时间线；学习建议只在末尾综合。不机械限定字数，也不为缩短删掉关键身份或让读者只剩抽象标签。来源集中在介绍旁；重要不确定性自然限定相应句子，无关未知与重复免责声明留内部记录。只从本轮作品支持的特点限定为本轮观察，不升级为长期人格。

用自然、明确的短句和短段落，英文、数字、专名回原文；术语首次解释其在案例的作用。区分作者认为、机构记录、从多个案例推断和尚未知。不用重复免责声明代替清楚措辞。摘要可以重新组织，逐字稿只能证据校正。

## 发布前语义复查

首页scope_summary只保留蒸馏数量/时间、实际平台和必要阶段限制，一条短句即可，不反复解释研究流程。完整scope和source_summary供读者按需展开。人物介绍从原文中选择少量身份、主要工作或代表实践短语写入highlights；只强调已有文字，不编新标签、不整段加粗，正文仍为一个自然段。

1. 对照材料核每个经历、结论、推荐理由、图源和跨平台版本；结论强于证据就收窄。
2. 通读内容简介，若读者仍不知具体内容、换标题仍适用，就补对象、动作或例子；删重复，不删条件。句数与长度只是提示，不替代语义判断。
3. 人物背景独立于作品窗口，事件日期与发表日期可辨；特点有实例和协作边界，背景、地图、解读与末尾方向一致且不重复。
4. 学习点有来源，未教透的基础写成可选延伸；五星表达学习价值与阅读优先级。
5. 逐字稿核源SHA、全文顺序、英文数字否定和故意错误例子；未确认更改留pending。
