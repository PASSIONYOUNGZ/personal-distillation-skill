# 内容理解、证据和文案质量

先读足够原文或完整稿，长材料按章节分块，最终核首尾和章节连接。搜索摘要、目录、章节列表只作定位，不替代全文。重要配图中的流程、代码、比较数据和操作路径必须实际查看，无法辨认的部分明确记录。

一张好卡片让新读者知道：讨论什么具体问题、作者怎样做、关键选择为什么、哪些条件下适用、可以学什么。短材料可以短，复杂方法保留解释和例子；不统一凑字数，也不把工具名清单当方法。

内部重要判断关联证据：来源ID、URL／本地快照、段落／时间／页码、支持的事实、本人自述／外部记录／分析、反例。输出选直接原链或时间定位，不堆无关引用。

| 位置 | 写什么 | 避免 |
| --- | --- | --- |
| 首页身份 | 姓名与简明身份定位，配已核头像、账号和范围入口 | 再放一段人物简介；宣传口号、猜职位、把封面人物当本人 |
| 认识这个人 | 一个完整段落说清主要角色、代表实践及有证据特点；来源集中可查 | 分四节写成第二条履历；逐年重复时间线；无关未知免责声明；预先列末尾学习建议 |
| 经历时间线 | 整体公开经历、角色变化及事件日期依据，不受作品选集窗口限制 | 用近几篇作品凑履历；文章发布日期冒充转岗日期；补未知月份 |
| 内容简介 | 通常1—3句，具体对象、问题、作者的动作或主要观点，必要条件 | “分享AI经验，值得学习”等通用空话；把推荐理由当内容介绍 |
| 内容解读 | 按原作实际结构讲清背景/问题、主要论点或过程、重要选择、原作例子和已讲到的结果；自然取舍模块 | 用简介再次概括长篇；理想流程安给作者；只剩抽象结论和工具名 |
| 观点与看法 | 按主题整理，每条用一两句清楚讲明一个有价值的判断；必要背景、归属与条件融入句子；展开原文和来源 | 短帖一律入选；重复标题与摘要；展开成第二份分析；把引用他人的观点写成本人独创 |
| 做事逻辑与方法 | 从具体作品解释问题、判断、行动和反馈如何联系，给证据与适用边界 | 只列“执行力、审美、长期主义”；一次实践冒充一贯习惯；团队结果全算本人 |
| 学习方向 | 直接教到、可迁移、需另学的基础分别说明 | 指定必学清单；没实践就写已掌握 |

例如“分享产品思维”过于空泛；若材料确实支持，可写“作者复盘一个写作工具：整篇重写让用户难以核对变化，于是改为逐项修改建议。文章解释建议如何定位到原句，以及用户怎样选择采纳。”这先交代原内容，再解释其做法；“值得学会控制自动化”留给学习分析。作者演示成功不等于我们已复现。

内容简介以让读者知道讲什么、是否值得进入全文为准。简单短帖不强凑三句，复杂材料不压成标签；桌面约1—3行是布局目标，不是字数上限。不能为适应固定列宽删必要条件、硬截断、缩成注释字号。手机和文字放大时自然增行。主体归属分清作者、团队同事与被转述者，不把同事的作品安给作者。

首页、人物介绍、经历和末尾学习方向各有职责。首页只用姓名与身份定位识别人；biography用一段连贯文字介绍整体角色、主要工作、代表实践与有依据特点，不再拆成多个履历小节。年份、转折及其证据放时间线；学习建议只在末尾综合。不机械限定字数，也不为缩短删掉关键身份或让读者只剩抽象标签。来源集中在介绍旁；重要不确定性自然限定相应句子，无关未知与重复免责声明留内部记录。只从本轮作品支持的特点限定为本轮观察，不升级为长期人格。

用自然、明确的短句和短段落，英文、数字、专名回原文；术语首次解释其在案例的作用。区分作者认为、机构记录、从多个案例推断和尚未知。不用重复免责声明代替清楚措辞。摘要可以重新组织，逐字稿只能证据校正。

## 发布前语义复查

**简介短，解读不能跟着缩。** 长视频/长文的“这篇内容讲了什么”是阅读核心，用analysis_sections保存实际有信息的小节，每项title和paragraphs。标题应反映该作品内容，例如“先让用户看到效果”“从购买记录到CLI安装”“更新只提示，不替用户决定”，不为每篇机械凑“背景/问题/方法/总结”四格。每节解释作者具体做了什么、为何这样做、如何衔接，保留理解所需的原作案例、失败与条件。没有教步骤的内容按论证与例子整理，不编教程；观点与看法明确reading_layer=viewpoint，常显summary表达完整判断，内部理解可用what，无需扩成空洞长文。

先读全文，列出原作主要部分/关键案例及定位，再写结构化整理。开头先让陌生读者知道人物、对象和起因，再顺着真实动作或论证解释，最后交代结果；标题负责帮助理解，不能用“一个私人需求也可以成为作品”这类抽象结论替代背景。具体物品、功能、参与者与前因后果首次出现时解释清楚，避免突然跳出数字、标记或工具名。成品演示可以解读其用途与交互，不能编造未公开的制作过程。

写完只看阅读正文，尝试复述：在讨论什么对象，为什么要做这件事，博主实际讲解、操作或检验了什么，各步骤或理由如何连接，结果怎样，作者据此提出什么判断？先把事情讲清楚，再提炼可借鉴之处；需要回原作猜测才能补上的连接必须补写。例如替换模型的实验，须说明原任务、替换了什么、保留了什么、前后结果及作者据此质疑的主张，不能只剩“做对照、注意归因边界”。教程则说明输入、部件作用与可见结果，不把术语串成清单。复杂材料宁可多解释几段，也不省掉关键案例；段落多少服从原作，不靠篇幅、学习建议或逐字稿代替理解。确有帮助的流程图、结果对照或操作画面应跟随相关解释，配图须亲看并写清支持什么，不用封面或无关截图充数。

新在线质量初筛任务的quality-spec每项增加comprehension数组：source_point（原作主要内容）、evidence_locator（真实原文/时间定位）、reader_section（实际解读小节title；viewpoint为“观点”，旧未分层短卡为“正文”）。accept-quality校验对应关系和条目输入，Agent仍须核主要内容是否被覆盖、有没有遗漏例子/失败/关键条件，不能只写“已读全文”过关。复杂作品用analysis_sections；仅真实短材料可声明brief。内部保留局限与诊断，直接影响结论的未知自然限定相应正文，不堆叠“简单解析”、重复覆盖提示、同一组原作链接及“阅读时留意”整块文字。

首页scope_summary只保留实际蒸馏数量/时间和取材平台。scope/source_summary即使折叠也只补充读者需要的范围信息；没有增量信息就不设折叠。调试阶段、架构预览、时区转换、筛选与去重细则、账号探查及日志放boundary或过程底稿，不复制进首页。材料没有补足原请求时须简短如实说明缺口，不能把删减后的集合称为完整最近N项。时间线常显事件日期、内容和来源链接；日期依据及材料发表日保留底稿，必要约数/未知在日期或正文就近表明。

人物介绍从原文中选择少量身份、主要工作或代表实践短语写入highlights；只强调已有文字，不编新标签、不整段加粗，正文仍为一个自然段。

1. 对照材料核每个经历、结论、推荐理由、图源和跨平台版本；结论强于证据就收窄。
2. 通读内容简介，若读者仍不知具体内容、换标题仍适用，就补对象、动作或例子；删重复，不删条件。句数与长度只是提示，不替代语义判断。
3. 人物背景独立于作品窗口，事件日期与发表日期可辨；特点有实例和协作边界，背景、地图、解读与末尾方向一致且不重复。
4. 学习点有来源，未教透的基础写成可选延伸；五星表达学习价值与阅读优先级。
5. 逐字稿核源SHA、全文顺序、英文数字否定和故意错误例子；未确认更改留pending。

按[data-and-batch](data-and-batch.md)的唯一合同写quality-spec，再accept-quality生成绑定回执：每项checks记录claim/evidence_locator/status=verified或qualified，并记录material_refs、coverage、remaining_gap；未读/需修改项不能写成verified。结构检查不能自动填“语义已核”；真正回读才记通过。资料不足提供诚实有限解读或保留获取索引，不用漂亮页面掩盖空内容。

## 阅读单元与做事逻辑

新任务在阅读后显式写reading_layer=deep/viewpoint。原始媒介kind与阅读层不同：完整论证的线程可以深读，短视频也可能只支持一个观点。复杂作品deep须有原作形状的analysis_sections；观点底稿what可以短，常显summary仍要还原本意，不能省掉“谁在什么情境下说的”。不按字数或是否存在视频自动分类。

观点与看法是经过理解后的编辑结果，不是短帖列表。先问原帖是否已经提出了清楚的区分、取舍、机制或有启发的具体经验；只有一句泛泛格言、求助、调侃或现象，不能靠我们补写例子和理由升级为三星。再把入选观点按少量实际主题组织，summary用通常一两句让人读懂判断的对象与含义，可以换一种更清楚的表达，但不能增加原作者没有的结论。引用他人的判断就在句中说清归属。常显只放这段观点；展开仅放实际原文与原链，不放重复分析、推荐理由、归属小节或同义标题。原文用documents保留准确文字，引用与主帖分清；译文不得冒充原文。

精选门槛在原帖本身：新功能/产品发布、模型或工具组合清单、品牌调侃或进度说明，即使可以附上正确的常识提醒，也未必构成值得精选的判断。评审时先拿掉我们添加的提醒与免责声明，问原作还留下了什么有辨识度的取舍、理由、失败经验或实例；没有就排除或留索引，不靠“还需要验证”“注意适用条件”等通用补语抬分。合格项少就如实少收，没有则隐藏模块；也不把未达标观点换放到方法栏，以泛化步骤继续包装。可用作背景的事实仍留背景，不按内容形式一概排除，不为维持栏目重复拆出已经深读的判断。

## 配图进入解读

“原文全文”不仅取决于有没有文字。遇到“我想这就是原因”“看图”等指代，先核其依赖的图表、引用帖或上文；文字本来很短可以完整保留，但不能据这几字声称已覆盖整项判断。必要上下文在已核材料与解读中交代清楚；没有读到就留缺口，不替作者推导立场。

阅读原作时保留图片与段落的对应关系，视频保留关键帧时间；写小节时从已核材料中选能说明对象、操作、对照或结果的图，写入analysis_sections[].images。图注说明读者该看什么并保留原作来源；一张静态帧不能单独证明连续动作、交互响应或模型能力。无需每节配图，也不设数量门槛；同一图不机械重复，封面只适合识别作品时就留在封面。

交付前逐篇对照现有材料与实际渲染数据：有合适原图却只留下载目录或封面时，补到对应解释旁；缺少理解所需画面时沿已放行路线有界补取。原作无合适图、尚未取得与已经看过但不适用分别记录在底稿，不写成同一种“无图”，不为配图重跑未变转写或全部采集。

原文展示与解读精简是两件事。原稿存档保留完整；观点与看法在可展示范围内优先使用完整原文，500字以内的短帖已有全文就完整保留段落，不再为精简取一句；超过500字也不自动截断，计数与例外沿[数据合同](data-and-batch.md#出版派生原文复核)。确因长文篇幅或实际转载边界需要节选时，尽量保留大部分主要内容，使读者仅凭展开部分就能理解对象、起因、判断和条件，并明确标识，不把“大部分”机械换算成固定比例。摘录须保留决定意思的转折、否定、对象与条件；不能逐项取前18字/固定token、把半句加“准确摘录”标签就交付，也不能把整理后的summary当原话。获取成功的短帖正文应贯通材料→documents→最终HTML；交付前展开核首尾和段落，不因“学习解读”或一般性转载顾虑批量清空已有原文。仅确实没有可展示的有效原文，或用户明确选择只放链接时，观点右侧直接显示平台来源链接，不设空的“查看／收起原文”。出版脚本改变documents/transcripts后，按记录合同核最终派生文字；原稿已审、HTML能打开或render-state哈希已更新，都不代表派生原文已核。

reading_units聚合时保留各来源卡与原稿。观点相似也要比较主语、条件、时间与否定，不把反驳合成支持；观点变化可以在一个单元中明确对照。几条信息贫乏的帖子合并也不能凭空变成有价值的论证。新表达本身须审阅，不能因为单篇已读就省略。单元quality-spec.unit_reviews逐来源映射source_point→reader_section，观点对应实际常显的“观点”，而不是已经不展示的分析段；参见记录合同。

profile.methods回答这个人如何做事，directions回答读者怎样借鉴。方法从证据支持的环节组织，不机械填完问题/取舍/行动/反馈/条件五格。只一例写“一次实践中的做法”；几个独立例子反复出现的行为可以归纳为本轮观察，仍不推断永久人格。证据kind区分observed、self_report、inference、quotation；引用明确原提出者，团队和被介绍者的劳动不要转成该人物自己的能力。必要反例、变化和条件就近说明，不常驻泛泛免责声明。

方法的标题应能指向行为机制，例如“先让差异可见，再要求用户接入”，而不是“重视产品体验”。若原作只抱怨接入成本，就写其产品判断，不能编出本人已实践的研发流程。说明“可尝试先做一个无需授权的演示”属于读者建议，与本人实际行动分开。

最终回读可用四问：新读者能否讲清原内容？每个关键结论是否比证据更强？跨来源归纳是否保留归属/变化？学习建议是否具体且有适用条件？需要修正就改内容，不能以哈希、章数、长字数或“已核”标记代替。

观点的视觉重点应落在判断本身：从summary原样选择一两处关键短语写入highlights，读者先扫重点也能辨认这条观点在谈什么；不能只加粗人名、整段加粗或为了强调改动原文。方法正文保留影响结论的归属和适用条件，重复的证据注记、原文行号及材料文件名转入可展开的辅助依据，来源链接去重后保留，不删除底稿。
