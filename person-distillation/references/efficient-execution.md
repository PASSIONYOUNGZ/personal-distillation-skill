# 在不压缩理解质量的前提下减少耗时

这份参考用于正式批量任务；不在普通启动时先跑发布回归或阅读维护者历史。准备的集中人工窗口仍先完成。优化对象是重复获取、无效等待、依赖返工和数据搬运，不能删掉全文理解、关键例子、必要画面或来源核对。

## 一条流水线，不为每篇从头搭脚本

1. 快速来源索引和集中准备完成后，连续枚举候选、按稳定ID去重。先读可便捷取得的正文/配文做[初筛](workflow.md#学习价值初筛)，再为保留与待核项取必要媒体。视频配文简短、像宣传或没有方法说明，不足以排除视频；若尚未读到原内容，留为待核并尽早取可用完整字幕、音轨和关键画面，避免写完其他作品后才换入。已读证据足以判断低价值的条目只留ID、评级、理由和依据。
2. 一次批量取得同平台必要元数据/字幕；按该平台实际速率串行或遵守限流。不同且不共享会话状态的来源可以有界并行，通常先从两个独立下载开始，实际限流/CPU/内存允许再调整。共享浏览器标签、登录状态和分页游标保持串行；不要同时导航同一标签或并发多个CPU模型。不要每篇重复读参考、建立环境、初始化模型、导入整个集合或重渲染整页。
3. 每取得一份合格稿就保存不可变原稿和版本。每批先做足以判断价值与同版关系的阅读，处理会影响当前入选边界的未决项，再集中写该批成稿；不把全网候选收齐设为写作前提。已关闭首次人工窗口后，独立的获取和理解可交错推进。对已核同版只补差异证据、复用完整稿，不重复转写；没有核准的候选关系不自动合并。
4. 字幕/同版正文已满足需要就复用，不再转写；跨平台核同版后只对缺证据的部分补取。ASR部署按实际缺口发生，不因任务“有视频”就安装所有依赖。
5. 批次内沿一个规范数据合同保存catalog/materials/cards/profile。新增ID、最早已核发布时间、同版关系和待核原因当步更新，下一批只补增量及不确定关系。必要目录已连续越过当前最早合格作品、且未决项不会改变前N项时停止继续向前扩取；边界改变再补受影响来源，不为重复确认而重读全部目录。直接使用现有构建入口；正文的analysis_sections同时进入Markdown和HTML，不用临时脚本删原稿、改回执或绕过.proposed手改合并。
6. 首批真实复杂作品先核原稿→有结构的解读→页面字段没有丢失，随后沿同一映射增量。正常研究只做本轮来源和产物验收，不跑整套发布测试。

## 本地语音转写

优先现有合格稿/便捷完整字幕，再按实际缺口选一条音轨+ASR路线。需要连续处理多份音频时使用video_tools.py whisper-batch：同一个进程加载一次模型，依次处理；不并发多个CPU模型抢资源。不要为省加载时间盲目降低模型/解码质量。

输入JSON是数组，每项`id/input/out`均为本次真实本地文件及输出路径。输出最好写任务内绝对路径；相对路径以命令cwd为准。外部CLI/下载仍用相应已验证能力，不把该命令当网络抓取器。

```text
python <skill>/scripts/video_tools.py whisper-batch --input <jobs.json> --out <new-batch-receipt.json> --model <existing-local-model> --workspace <workspace>
```

每项成功立即保存；单项失败继续其他项目，最终回执及退出码报告失败。只有音频SHA、引擎版本、模型本地文件签名、参数和稿件内容校验一致才缓存复用；未登记的既有文件不覆盖。模型签名是当前缓存前提检查，不是模型真实性证明；新模型仍依部署来源及短样本确认。SenseVoice等路线按真实条件选择，不因加入此批命令固定所有视频引擎。

## 跨任务复用运行时

研究资料与依赖目录分开：每个任务保持自己的request、原稿、笔记、environment.json和`.distill/runtime-binding.json`；同一使用者的Python/依赖/模型只在受管理缓存安装一次。缓存键包含Python实现与ABI、系统/架构、media或whisper依赖合同版本、模型名称及CPU/int8配置，不包含人物和任务目录。核心图文研究仍只用标准库，缺视频处理能力时才运行bootstrap。

位置依次为命令显式`--runtime-dir`（准确目录）、`PERSON_DISTILLATION_RUNTIME_ROOT`（缓存根）、已声明的`CODEX_HOME/person-distillation/runtime`，否则当前用户系统缓存。Windows路径过长时用已授权的短缓存根，不修改系统长路径、PATH、代理或全局Python。没有显式新根时，任务已登记且有本工具所有权标记的旧任务运行时可以继续复用；不扫描整机、不借其他账号环境、不删除旧目录。依赖合同不同就选择新缓存，不原地改变一个已按其他合同登记的环境。

```text
python <skill>/scripts/bootstrap.py --workspace <任务目录> --profile whisper --download-model
python <skill>/scripts/bootstrap.py --workspace <任务目录> --profile whisper --download-model --apply
```

需要以Pillow读取静态帧、做缩略图或拼接审阅图时，在计划和apply都加`--image-review`；media/whisper都会在自己的合同中补Pillow并核PIL.Image/ImageOps/ImageDraw。执行实际图像脚本时使用回执中的准确Python路径，不依赖共享或系统解释器恰好有PIL。纯字幕/音轨任务不添加该开关；现有video_tools的extract是抽音频，不是帧提取命令。静态帧仍用已验证FFmpeg及明确时间点，不能把拼图自动选作原作封面。

第一次创建专用venv、从官方源按需安装和下载。下一任务使用同一命令，先做本地import、ABI/依赖版本、FFmpeg/yt-dlp执行与必要模型文件检查；通过后只绑定该任务，不重复ensurepip、pip install或模型联网查询。模型首次下载记录revision及SHA256；warm核必要JSON和文件签名，改变/缺失时对已记录revision强制重新获取，再比对已登记哈希，不能把下载器返回旧坏文件当修好。未变签名是缓存前提，不是模型真伪或转写质量证明。只安装需要的一条路线；tiny仅用于低资源/安装烟测，不替代正式质量选择。

安装使用跨进程OS锁与原子完成回执；并发任务等待同一缓存，不抢写。进程退出会释放锁，等待超时记失败，不按锁文件年龄强抢；中断的环境没有完成标记，下一次先探测实际能力再补缺。非本工具管理的已有目录拒绝覆盖。没有通过版本/import/可执行文件核查，或模型不完整，就不写`dependencies_ready`；失败的旧任务binding标为`verification_failed`，原任务数据保留。bootstrap仍不把字幕、ASR或平台记ready：首次真正使用一条媒体路线，必须完成实际短样本、首尾与时长核对。

Python核心可运行不等于ASR有兼容wheel；缺轮子时选合适的已授权宿主解释器或其他已就绪路线。运行时复用仅消除重复部署，不能降低模型/解码质量、跳过必要原稿理解、关键画面或语义审阅。

## 记录能解释的时间

普通任务沿[本地耗时埋点](performance-tracing.md)默认记录。主要阶段和实际批次留开始/结束，不要求每次DOM读取写长报告。可在已有Python采集驱动中使用performance_trace.span或runlog.measure包装真实批次；开始先落盘，异常/中断可定位。阶段名沿runlog.STAGES，多个独立阶段不相加冒充墙钟。

bootstrap回执区分cold、warm、legacy-reuse、repair及warm-model-download，记录总窗口、锁等待、本地复验、实际安装/下载起止及尝试次数；warm不是零耗时，也不等于真实转写已验证。ASR拆开加载、逐项计算与缓存，单条转写也以引擎实际报告的音频duration记录media_seconds。下载和用户等待分别记。自定义获取脚本沿acquisition.record保存实际获取观察及source_id、route_id和起止；需要外层批次窗口时用performance_trace.span(kind=phase)，不为同一工具动作重复记时。不要另造一套未汇入报告的成功状态。已有回执缺平台或起止时保留缺口，不从文件mtime或整段阅读窗口倒算。Agent在长篇阅读/写作前后记录真实时间区间；这表示该工作窗口，不能再精分成未记录的模型计算和等待。verify自动生成JSON、Markdown和CSV，显示阶段/操作排行、重试、复用、重叠、未闭合区间与最长空档；不要将几秒命令日志说成整轮耗时。

先比较同等证据与解读质量，再测端到端速度。单元测试证明加载次数/缓存/断点规则，不证明新机任务能在固定分钟内完成；记录新实测之前不宣传加速倍数或承诺30项完成时间。
