# 获取控制与范围完整性

先把可工作的路径跑通，再扩数量。工具命令成功、HTTP 200、登录头像、第三方末页都不能单独证明材料取得或范围完成。以下控制由Agent执行；脚本只计算已记录证据，不能替代真实浏览器观察。

## 三个不同的检查点

人工清单：人物/范围→少量身份索引→实际浏览器→必要入口轻探和有界恢复→集中具体人工动作。不要等分页收齐。

逐来源批量放行：人工处理后复验该会话，作者目录样本与一篇正文可读；正式分页中的首次增量/明确末页再验证目录连续性。

范围完成：各必要目录越过本轮边界并核去重；媒体/ASR用于已保留作品，也用于必须读取媒体才能判断学习价值的待核候选；选中路线后补短样本，不要求先入选才能取稿。这三个检查点不能互作前置循环。

- 原生作者页实际要求登录且挡住所需目录／全文：准备期集中给登录待办，写浏览器、URL、解锁能力。已知需要登录时不先兜遍第三方站。完成后验证原来失败的目录／正文动作，不只看头像。
- 原生浏览器只读正常、CLI失败：沿用浏览器；不同工具的会话不共享，不推断账号失效。
- 已有登录浏览器不在工具清单：记宿主能力缺口，按宿主支持方式接入；不能假定电脑上的Chrome可控，不能用别的工具私读浏览器会话。平台登录不修复浏览器工具连接。
- 先取轻量元数据，目录含置顶／回复／转载时分别标记。试读材料可复用；不要把“测试”变成每个平台跑完全部引擎。
- 先集中完成所有必要主流平台的轻探，再一次汇总人工连接／登录／验证待办并统一复验。首次人工窗口未关闭时，已就绪平台只留探测样本，不先扩量或写临时卡。用户明确跳过才调整范围；后续运行中的局部故障另按接续处理。

## 失败分类与停止规则

同一路线指同一平台、能力和访问方式，不靠换域名／查询参数重置预算。准备默认一条首选路线及一条有依据的正常备用路线；非限流的暂时故障最多一次重试。连续无进展约3分钟就保存现状并切换／报告依赖；高成本媒体按时长另设预算。持续取得新材料的正常分页不受这个故障预算限制。预算消耗不能偷偷缩小用户任务。

| 实际证据 | 判断与下一步 | 不做什么 |
| --- | --- | --- |
| 沙箱连接拒绝、代理连接失败 | 记transport；按宿主审批使用允许的联网工具，随后复验同一轻量请求 | 不按平台逐个重试，不擅改代理／系统网络 |
| 控制工具超时，标签可能已创建 | 先取现有标签列表，复用已创建标签；一次操作＋一次局部DOM读取，按实际延迟用45—60秒调用预算 | 不反复建标签、重置或重登录；总耗时不等于网页加载时间 |
| HTTP 200但业务码限流，或429／明确频率提示 | 停该路线，遵守Retry-After；没有恢复依据则当前批次不重试 | 不并发轰炸、不换接口／账号／代理规避限流 |
| 401／403／412，尚无登录页面证据 | 记该访问方式受限；正常原生浏览器至多核一次提示 | 不直接诊断“未登录”“零内容” |
| 0字节、导航壳、静态抽取无正文 | 换可渲染原生页面，核作者、正文、结尾；浏览器也受限再分类 | 不把HTTP成功、导航字数或简介当全文 |
| CAPTCHA／验证页 | 首次准备并入集中人工窗口，统一复验后才采集；运行中再局部暂停依赖 | 不绕验证、不索取Cookie |
| 会员边界／付费墙 | 仅取公开原作或用户已有授权导入，保留缺口 | 不借聚合镜像绕付费，不默认购买 |
| 证书过期 | 停该来源，改用正常可信原站或其他证据 | 不关闭TLS校验 |
| 点击翻页／日期按钮后稳定ID没有新增 | 记stalled；检查加载状态、排序、按钮含义、游标；只有明确条件变化才再试 | 不把按钮高亮当列表变化，不把无新增当末页 |
| 搜索快照、近7日热门、精选库 | 只作候选／身份线索，已知ID可补正文 | 不换猜测参数扫全库来证明“最新N项” |

用`scripts/acquisition.py --workspace <工作区> --input <observation.json>`追加`.distill/acquisition-log.jsonl`。正式获取purpose默认collection，首次人工窗口未关闭就拒绝；成功远程操作另核该source_id/capability/route_id；准备观察显式purpose=probe，probe_round为initial，每source_id/条件周期目录成功轻探至多两次、其他能力一个样本；人工处理后recheck须附change_evidence，不能靠换round无限翻页。探测样本放接入回执，不提前import到正式蒸馏集合。输入骨架在assets/acquisition.example.json；记录能力、方式、证据、耗时、响应和ID，不存请求头／Cookie。脚本计算new_ids、失败类别与停止建议，不抓取或代替真实观察；Agent还必须在浏览器动作前遵守此门槛。

默认每平台串行。只有互不影响的来源可并行；某来源出现频率提示时该来源的目录／正文任务一起降速或停止，不让另一个分支继续撞限制。成功缓存复用，失败单项隔离，正文、图片、音频和ASR分别记状态。

## 如何证明“最近N项”

1. 固定实际观察时间as_of、时区、账号身份与范围；列表置顶不参加排序，纯转发／他人提及不计本人独立作品。引用帖含本人实质表达可计；长文附属分享帖与文章核同版后合并。回复类型单列，不静默与原作混计。
2. 每个已确认且在范围内的原生作者目录，从近期头部连续保存ID与原始日期，至少验证一次分页增量。网页虚拟列表边滚边存，不能最后只取可见的20条。官方API／作者本人导出可作等价目录，但须核其权限、截断、排序和缺页。
3. 合并候选，核跨平台版本、按原作发表时间排序，暂选N项；每平台继续至**严格早于第N项所在日期**或有证据的实际末页，再处理边界同日项。日期不精确时按天核完；日期未知的候选会影响最新顺序，先保留缺口。数量去重后减少就更新边界并补齐。
4. 时间范围要覆盖区间上界至严格早于下界；数量＋时间需核区间内数量与边界。确实不足N项时，只有所有相关目录均有实际末页／区间覆盖证据才可报告“范围内仅M项”，不能用搜索无结果证明耗尽。
5. source-ledger列清所有已确认来源，包括status=limited的受限者；同平台多个账号／目录各有稳定source_id，不能合并平台名后漏掉第二个账号。scope-review按source_id逐一写目录类型、头部、连续性、最旧连续日期、停止依据和证据定位。任何主流来源仍不明就不能声称跨平台最新集合完整。用户明确限定来源时只核所选来源，记录这一边界。

范围是“本次已确认来源中的最新N项”，不能宣称全网绝对无遗漏。热门／精选／镜像即使遍历到末页，仍不能变成完整原生目录。代表性抽样另记用户选择和有界候选依据，不套最新N的排序保证。

## 材料与中间成果

首次集中准备通过后，得到可读全文就分小批理解：候选登记→原文版本与SHA→全文及重要图核读→临时selection（status=provisional）→内容卡。准备前样本只验证接入，不写分析卡。暂定集合变化保留候选卡，最终HTML只包含最终入选；外部引用保持辅助证据。

已完成首次准备后，运行中的目录受阻不让已取得全文闲置，也不能靠易取文章凑满数量。原范围完成要求本轮initial_preparation_complete、selection.status=final、scope-review与当前请求／ID一致，成品还需结构和绑定quality-review通过。视觉／离线实际状态另按[data-and-batch](data-and-batch.md)记录：工具未执行可明示后交文件，真实failed须修复，不虚报全部验收。准备后局部HTML可称阶段版交付，准备前不生成研究版。

## Windows与长材料

复杂Python／正则保存为项目内具名脚本，用参数数组调用；不要多层PowerShell引号拼接。脚本名避开inspect.py、json.py、email.py、typing.py、http.py等标准库名。仅在当前任务目录或已明确的工具路径搜索，不全盘扫其他对话。

长网页／参考保存完整文件后按标题、行号或段号分块读；记录已读区间与总范围，结尾另核。输出截断不能算全文已读。原稿不因缩短工具输出而被截断，分析摘要与完整原稿分开保存。

## 低负担耗时记录

沿已有acquisition-log及run-log记真实阶段／有效动作批次、对象和版本、路线、起止或工具返回耗时、结果与产物、是否复用。浏览器未给耗时就留未知，不以文件mtime或整轮对话窗口推算某工具耗时；不要求每次DOM读取写长报告。人工待办发出和答复分别留事件，并发调用耗时不直接相加成墙钟。

优先减少同条件重试、重复取稿、临交付补结构和模板返工。日志更新不代表材料或结论变化，不应使已审内容失效；真正改变材料、选择、解释或配置才重审受影响部分。准备期不为记录或离线样例拖延集中人工窗口。

浏览器或临时脚本取得真实正文、目录批次、媒体后，也用现有acquisition记录接口保存对应回执；不只CLI下载才留账。没有工具计时时省略耗时，已保存的记录不重复登记，历史缺日志不事后编造采集动作。字段与命令沿[data-and-batch](data-and-batch.md#正确启动与审阅命令)。
